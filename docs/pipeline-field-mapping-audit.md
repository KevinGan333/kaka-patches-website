## Key Findings

### ✅ Working Correctly

1. **Field 1–6, 8–19**: Form → API → DB → Admin pipeline is complete with no gaps.
2. **Server total recalculation** (Field 7): `perDesign × designs` computed server-side, never trusts client.
3. **Backward compatibility**: `patchType` and `quantity` legacy fields preserved; `product_category` complements `patch_type`.
4. **Artwork pipeline**: File → Vercel Blob → `artwork_url`/`artwork_filename` → email attachment fallback → admin display.
5. **MOQ validation**: Now advisory-only — 3-tier (below 100 = sample eval, 100-199 = selected constructions, 200+ = standard). Never blocks submission.
6. **Honeypot + Rate limiting**: In-memory anti-spam working (5 req/min/IP).
7. **Historical data**: All existing columns preserved; new columns nullable; no destructive changes.
8. **Admin detail**: All 29 fields displayed across Product Details, Project Info, Artwork, Marketing Attribution, System Info sections.

### ✅ Fixed During Audit

1. **UTM capture** (Fields 20–22): QuoteForm now reads `utm_source`, `utm_medium`, `utm_campaign` from URL query params and sends them to the API. Previously the API, DB, email, and admin were all ready but the form never populated the fields.

### ⚠ Design Notes

1. **Per-design quantities as structured data**: Currently `quantity_per_design` is a single value (one quantity applied to all designs). For multi-design projects where designs have different quantities, this would need to be a JSON array (`[{design: 1, qty: 500}, {design: 2, qty: 300}]`). The current implementation is adequate for the common case where all designs have the same quantity. **Recommendation**: Add a "mixed quantities" toggle in Step 1 for multi-design orders.
2. **Total quantity display in admin list**: Shows total `quantity` column only. Should ideally also show `per-design qty × designs` breakdown.
3. **CSV export**: Already maps all fields including UTM and new columns (`exportQuoteRequestsCsv()` in `quote-db.ts`).
